PHASE 4: MONITORING COVERAGE
===========================================================

**Say out loud, before touching it:** "Writing to Justin's Gatus on vps1." If the
target does not clearly resolve to that instance, stop.

Everything that can fail silently needs a monitor:

- **Services**: HTTP check against a health endpoint that reflects *real* health
  (body condition, not just status 200).
- **Scheduled jobs**: a **push** endpoint with a heartbeat slightly longer than the
  expected interval, beaten by `hc-beat <slug>` / `gatus-push`. "It has no URL" is
  not an exemption.

Add endpoints in `agent-infra/tools/gatus_config.py` (never hand-edit the live
config, regeneration overwrites it), regenerate, deploy to vps1, and confirm the
endpoint shows in `/api/v1/endpoints/statuses`. Never report coverage you did not confirm.

**Gatus blind spot:** a push endpoint that has never received a beat does not appear
in statuses and never goes red. List configured push endpoints missing from statuses;
each one is a job that has never succeeded since it was added.

**Audit existing endpoints for whether they check something real.** A check on a page
that returns 200 no matter what is worse than none, because it says covered when it is not.

**Confirm the external watchdog is alive** (`vps1-watchdog.timer` and
`gatus-watch.timer` on vps4). A dead monitoring box looks exactly like everything being fine.
